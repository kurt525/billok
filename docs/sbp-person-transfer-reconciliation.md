# BillOK Issue #1 / 4.3.2: официальный список банков СБП

Основной источник для допуска банков к переводам физическим лицам по номеру:
https://sbp.nspk.ru/participants?type=person&labels=person-transfer

Вторичный источник: eav93/sbp, его локальный снимок — src/lib/sbp-bank-catalog.json.

возможность перевода физлицу по номеру телефона. Разница счётчиков 204–195
не является доказательством отсутствия ровно 9 банков.

## Аудитор без права публикации

scripts/audit-sbp-person-transfers.mjs принимает локальную выгрузку,
происхождение которой подтверждено ответственным. Программа не меняет
список банков и не создаёт релизы или банковские QR. Пример схемы
(два имени приведены лишь для формата: реальная выгрузка должна быть полной,
не содержать придуманного состава и включать 100–600 банков):

    {
      "source": "https://sbp.nspk.ru/participants?type=person&labels=person-transfer",
      "type": "person",
      "labels": ["person-transfer"],
      "fetchedAt": "2026-11-09T12:00:00Z",
      "banks": [
        {"name": "Имя банка из официального источника"},
        {"name": "Второе подтверждённое имя"}
      ]
    }

Оператор обязан подтвердить исходный официальный источник,
дату и факт применения фильтра person-transfer — сам JSON-файл
не является криптографическим подтверждением происхождения.
Поле nspkId допустимо только для независимым образом проверенного
12-значного идентификатора участника НСПК. Не использовать числовой
id карточки сайта, slug или порядковый номер вместо nspkId.
Не включать секреты, токены, cookies или персональные данные.

Команды после появления подтверждённой выгрузки:

    npm run sbp:person:audit -- --snapshot /path/to/official-person-transfer.json --report /path/to/report.json
    npm run sbp:sync:test

Отчёт разделяет matched, unmatchedOfficial, unmatchedLocal и ambiguous.
Код 3 означает необходимость ручного разбора расхождений,
код 1 — ошибку входных данных. Ни один результат не включает
банки автоматически. Сопоставление только по 12-значному
проверенному nspkId или по единственному точному нормализованному
названию; никакого нечёткого угадывания переименованных банков.

## 4.3.2.3.1 — безопасный предпросмотр перехода (без публикации)

После получения полного подтверждённого снимка применить:

    npm run sbp:person:plan -- --snapshot /path/to/official-person-transfer.json --report /path/to/review-only-plan.json

Команда только читает исходный локальный C2B-каталог и операторский
официальный снимок; пишет отчёт в отдельный файл за пределами
работающего каталога. В нём показаны сохранённые внутренние
идентификаторы, предложенные новые подтверждённые идентификаторы
участников НСПК, выбывшие банки (их ID остаются, но становятся
неактивны), причины блокировки и неразрешённые логотипы.
Ни один логотип не включается в кандидат автоматически до проверки
прав: используется icon=null.

Любые сопоставления только по названию, неоднозначности или новые
банки без подтверждённого 12-значного идентификатора блокируют
даже формирование кандидатного каталога. Наличие готового кандидата
не является разрешением на публикацию или переключение
справочника приложения. Никакой самостоятельной проверки
происхождения файла JSON не происходит — ответственное лицо
должно подтвердить её независимо.

Старый C2B-синхронизатор теперь отказывается работать с
любым каталогом, чей sourceSystem не равен исходной C2B-модели:
он не сможет случайно оживить исключённые банки после перехода
на новый список переводов по номеру. При принятии нового списка
потребуется отдельная контролируемая система обновления
по официальному person-transfer и согласованная приёмка.
