## Автоматизированная сверка на VPS

Сверка с eav93/sbp выполняется собственным systemd timer на VPS,
а не по расписанию GitHub Actions. Плановый запуск ежедневно в
05:20 UTC (08:20 по московскому времени).

- Скрипт scripts/ops/sbp-catalog-poll.sh использует отдельную временную
  рабочую копию репозитория и существующий Node.js 22.23.4;
  не трогает сайт, базу данных и CI runner.
- Новые участники добавляются с текстовыми метками до появления иконок.
  Устаревшие записи остаются для ранее сохранённых настроек профиля,
  но скрыты из нового выбора и помечены как неактуальные.
- Переименования обновляют названия по стабильным ID НСПК.
  Для первоначальных восьми банков сохранены внутренние ID BillOK.
- Ошибочные данные, дубликаты и массовые удаления блокируются.
  Изменение одной лишь даты обновления не создаёт коммита.
- При реальном изменении скрипт создаёт отдельную ветку и PR;
  если PR ещё открыт, используется та же ветка с очередным
  обычным коммитом. CI на self-hosted runner запускается уже
  действующим GitHub-триггером push; дополнительных CI workflow
  и GitHub-hosted runner не требуется.
- Автоматического слияния, удаления записей из пользовательских
  профилей и выкладки на сайт нет.

### Включение после слияния PR #3 в main

Устанавливать и включать таймер нужно отдельно, после принятия
соответствующих изменений в main (здесь приведены команды администратора):

1. Создать системный путь /usr/local/libexec/billok.
2. Скопировать **оба** доверенных файла scripts/ops/sbp-catalog-poll.sh
   и scripts/ops/sbp-catalog-trust.sh в /usr/local/libexec/billok/
   с правами 0755. Скрипт сверки проверяет JS-файлы повторно используемой
   ветки PR по текущему main **до их запуска**. Если ветка изменена вручную
   или отстала от main по исполняемым файлам, автоматизация прекращает работу
   без коммита и требует ручной проверки. Также запрещено менять в
   автоматически созданном PR что-либо, кроме JSON-каталога:
   код, конфигурацию CI, файлы приложения и права исполняемых файлов.
   Даже внутри JSON сохраняются ранее выданные внутренние ID, ID НСПК,
   пути к локальным логотипам и источник реестра. Допустимы изменения
   названий, статуса активности и добавление новых банков.
   Дата снимка должна быть корректной, не старее принятого каталога
   и не более чем на сутки впереди времени проверки, чтобы случайная
   дата из далёкого будущего не блокировала следующие сверки.
   Подменённые symlink отклоняются.
3. Скопировать deploy/systemd/billok-sbp-catalog-sync.service и
   deploy/systemd/billok-sbp-catalog-sync.timer в /etc/systemd/system/.
4. Выполнить systemctl daemon-reload и
   systemctl enable --now billok-sbp-catalog-sync.timer.
5. Проверить systemctl list-timers и журнал
   journalctl -u billok-sbp-catalog-sync.service.

Пользователь службы sentinelx должен иметь доступ к GitHub
для чтения и права создания ветки и PR репозитория. Служба
использует systemd StateDirectory=billok-sbp-sync
для защищённого локального каталога задач.

До включения таймера автоматических проверок не будет.
Сверка каталога НСПК сама по себе не подтверждает наличие
банковской лицензии и возможность перевода физлицу по телефону.
