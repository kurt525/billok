# BillOK

BillOK — русскоязычное приложение для ручного разделения ресторанного чека между участниками. **Проект ещё не опубликован:** данные и учётные записи на этапе разработки тестовые; рабочая учётная запись владельца не создана.

Основано на [ShareTab](https://github.com/sw-carlos-cristobal/sharetab) Карлоса Кристобаля. Лицензия исходного кода — [MIT](LICENSE).

## Что реализуется

- Только ручной ввод позиций чека; без OCR, загрузки фотографий чеков и AI-распознавания.
- Суммы в рублях и копейках; доли блюд, один плательщик, персональные задолженности и добровольные чаевые без добавочного налога.
- Вход зарегистрированных пользователей по Passkey, регистрация только по приглашению, гостевые участники по ссылкам.
- Реквизиты СБП для возмещения: номер телефона, банк и сумма; без Venmo, платежных QR и внешних C2C-ссылок.
- Один язык — русский; мобильный интерфейс и PWA для Android.

Фактическая приёмка проводится строго по [Issue #1](https://github.com/kurt525/billok/issues/1). Технический журнал изменений и результаты CI — в [PR #3](https://github.com/kurt525/billok/pull/3). Issue содержит требования и checkbox, а не журнал тестов.

## Локальная разработка и проверки

Необходимо: Node.js **22.23.4**, npm, PostgreSQL и браузер Chromium для Playwright. Использовать **отдельную тестовую БД**. Для локального запуска допустимы только тестовые значения в локальном `.env`; этот файл не коммитить и не копировать в production.

    npm ci --legacy-peer-deps
    npx prisma generate
    npm run dev

Управлять схемой и тестовыми записями можно только в согласованной среде, не в действующей БД других сайтов.

Основные проверки:

    npm run lint:i18n
    npm run lint
    npx tsc --noEmit
    npm test
    python3 scripts/test_billok_legacy_cleanup.py
    python3 scripts/test_billok_venmo_removal.py

CI на собственном `ci-runner` проверяет **пять обязательных заданий**, включая мобильный Chromium (320–720 px). Приёмка кода — только после 5/5 PASS. История выполненных заданий хранится в PR #3.

## Подготовка Docker и HTTPS — не инструкция к немедленной публикации

`docker/docker-compose.yml` предоставляет приложению порт **только 127.0.0.1:3000**; внешний доступ возможен лишь через отдельный Nginx reverse proxy. В production **запрещено** передавать ключи и пароли через `docker/.env` или Compose environment.

- [Защищённые production-секреты](ops/billok/PRODUCTION-SECRETS.md): файлы в `/etc/billok/secrets`, root:root, каталог 0700, файлы 0600, монтирование read-only.
- [HTTPS и Let's Encrypt](ops/billok/HTTPS-PREDEPLOY.md): отдельные ACME- и HTTPS-конфигурации, проверка Nginx и сертификатов без изменения других сайтов.
- [Защита от непреднамеренных релизов](.github/workflows/auto-release.yml): автоматическое развёртывание, продвижение `stable` и публикация Docker-образов запрещены до отдельного разрешения владельца.

**Не выполнять `docker compose up -d` на рабочем VPS и не выпускать production-сертификаты без отдельной приёмки и разрешения владельца.** Пункты 8.10 и 8.11 ещё ожидают заключительных проверок и не дают права публиковать BillOK.

## Информационная безопасность

Секреты, реальные учётные данные, ключи Passkey/SMTP, приватные токены и содержимое базы никогда не включаются в Git, Docker build, CI-артефакты или журналы. Node.js 22.23.4 на `ci-runner` должен сохраняться при очистке диска.
