# Обязательные инструкции для работы с BillOK

Действуют для всех разработчиков и AI-агентов во всём репозитории. Читать этот файл перед подготовкой любого нового TASK-BILLOK и перед продолжением существующей задачи, в том числе в новом чате. История чата не является источником текущего номера версии: источник истины — актуальная ветка main и [регламент версионирования](docs/versioning.md). При противоречии с историческими указаниями ShareTab применять действующие правила BillOK.

## Версионирование — обязательный этап каждой задачи

- При составлении Issue определить тип изменения и поставить ровно одну метку: `version:major`, `version:minor` или `version:patch`. При смешанных изменениях выбрать старший тип.
- MAJOR — несовместимые или принципиальные изменения; до реализации получить и зафиксировать явное согласование владельца. MINOR — новая совместимая функциональность. PATCH — исправления без новых возможностей и нарушения совместимости.
- Перед реализацией и перед коммитом сверить версию актуального main. Увеличить соответствующую компоненту MAJOR.MINOR.PATCH один раз на выпуск задачи; младшие компоненты обнулить. Синхронно обновить `package.json`, верхнее поле version и `packages[""].version` в `package-lock.json`. Не менять зависимости только ради номера.
- Обновить CHANGELOG.md и серверный манифест `src/server/lib/billok-release.json` (версия, TASK, русское название, точный номер PR); в описании PR указать тип, предыдущую и новую версию, обоснование и `Closes #<номер Issue>`. Если main изменился, пересчитать от фактической версии перед слиянием. Не переписывать историю.
- Повтор CI или исправление ещё не выпущенной задачи не увеличивают версию повторно. Проверка состояния, чтение кода и редактирование метаданных Issue/PR сами по себе не являются выпуском.
- Сначала адресные проверки, затем полный CI 5/5 на одном SHA. При случайном сбое повторить только упавшее задание без нового коммита. Отметить задачи Issue после приёмки. Не сливать PR и не менять защиту развёртывания без согласования владельца.
- Версия считается установленной только после подтверждённой production-выкладки. Номер версии и SHA в панели администрирования доступны только системному владельцу.

## Рабочие ограничения

Выполнять только согласованный Issue, не смешивать разделы. В Issue — задачи и отметки, в PR — описание и результаты проверок на русском языке. BillOK — ручные чеки, RUB, Passkey, приглашения, русский мобильный интерфейс. Не возвращать OCR, альтернативные способы входа или публичный доступ к служебным сведениям. Не затрагивать другие проекты на VPS.
