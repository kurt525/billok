# BillOK: production-секреты (Issue #1, пункт 8.11)

**Сайт ещё не опубликован.** Этот пункт обеспечивает безопасную
конфигурацию будущего production, но не разрешает его запуск. Доступ через
HTTPS — отдельный пункт 8.10; предрелизная очистка — раздел 9.

## Принцип

Пароли PostgreSQL и SMTP, ключи AUTH_SECRET, NEXTAUTH_SECRET и опциональный
VAPID private key не хранятся в GitHub, GitHub Actions Secrets, .env,
Dockerfile, аргументах docker build и Docker Compose environment.

Источник только на сервере приложения: каталог /etc/billok/secrets,
принадлежащий root и имеющий права 0700. Четыре обязательных файла:

| Файл                 | Назначение                                             |
| -------------------- | ------------------------------------------------------ |
| database-password    | Случайный пароль БД (64 hex-символа или больше)        |
| auth-secret          | Ключ Auth.js (64 hex-символа или больше)               |
| nextauth-secret      | Ключ совместимости Auth.js (64 hex-символа или больше) |
| reg-ru-smtp-password | Пароль почтового ящика REG.RU (формат провайдера)      |

Каждый файл принадлежит root:root с правами 0600. Символические ссылки,
пустые или открытые другим пользователям файлы отклоняются. Пароль SMTP
не печатать в консоли и не отправлять в чат. Уже сохранённый файл
reg-ru-smtp-password не заменять: SMTP AUTH ранее прошёл проверку.

Для будущих push-уведомлений допускается отдельный необязательный
файл vapid-private-key (root:root, 0600). Если его нет, приватный ключ
не генерируется и не включается автоматически.

## Создание секретов администратором VPS

**Выполнять только после согласования production-подготовки с владельцем.**
Создание и настройка не выполняются автоматически через CI. В root-консоли
основного VPS:

    install -d -o root -g root -m 0700 /etc/billok/secrets

Одноразово создать недостающие ключи, не переписывая существующие:

    umask 077
    for f in database-password auth-secret nextauth-secret; do
      if [ ! -e "/etc/billok/secrets/$f" ]; then
        openssl rand -hex 32 > "/etc/billok/secrets/$f"
      fi
    done

После этого убедиться, что все четыре файла присутствуют, принадлежат
root и имеют права 0600. НИКОГДА не выполнять cat или печать значений.

    stat -c '%n uid=%u mode=%a size=%s' /etc/billok/secrets/database-password /etc/billok/secrets/auth-secret /etc/billok/secrets/nextauth-secret /etc/billok/secrets/reg-ru-smtp-password

Включить защищённое резервирование **секретов отдельно от кода и
общих логов**, с ограниченным доступом. Не включать этот каталог в
общедоступные архивы или каталог Docker build.

## Путь секретов в контейнере

Docker Compose монтирует каталог только для чтения:

- host: /etc/billok/secrets
- container: /run/billok-secrets
- read_only: true, create_host_path: false

Скрипт docker/load-secrets.sh проверяет владельца и права до запуска
PostgreSQL; ключи загружаются только в память процесса. Нельзя
добавлять их в переменные окружения Compose: при запуске они появятся
в docker inspect. Если в environment уже передан секрет, контейнер
отказывается стартовать.

Сборочный контекст исключает .env-файлы, .npmrc и файлы ключей.
Значения ключей не входят в образ, логи и вывод конфигурации. При
инициализации PostgreSQL пароль проходит через stdin, а не аргумент psql
командной строки. Никогда не запускать sh -x, set -x или printenv для
приложения.

## Контроль без раскрытия секретов

1. Проверить docker compose config: в environment сервиса sharetab
   **нет** DB_PASSWORD, AUTH_SECRET, NEXTAUTH_SECRET, DATABASE_URL,
   EMAIL_SERVER_PASSWORD, WEB_PUSH_VAPID_PRIVATE_KEY.
2. Проверить монтирование только для чтения и привязку порта к 127.0.0.1.
3. Проверить права root:root/0700 и root:root/0600, не читая содержимое.
4. Проверить отказ запуска при недостающем файле, неправильных правах и
   попытке передать ключ через Docker environment.
5. Выполнить python3 scripts/test_billok_production_secrets.py.
6. Принять пункт Issue #1 после полного CI 5/5 и проверки защищённого
   хранения на реальном сервере. Описание приёмки хранится в PR #3.

на основном VPS **не подтверждено**; они не создавались данным
изменением. Регистрация рабочей учётной записи владельца и публикация
проекта не выполнялись.
