# BillOK — обслуживание ci-runner (Issue #1, 8.8; TASK-BILLOK-009)

Целевой сервер: msk-1-vm-0w12; сервис
actions.runner.kurt525-billok.msk-1-vm-0w12-billok.service.
Node.js 22.23.4 не удалять.

## Мониторинг

ci-runner-cleanup status без привилегий выводит свободное место на / и
/srv/ci-storage, проверяет монтирование рабочего каталога BillOK, сервис
GitHub runner и версию Node. Все пять обязательных CI jobs вызывают эту
проверку до выполнения основного задания. При >=80% диска — предупреждение,
при >=90%, отсутствии монтирования, Node или сервиса — ошибка.
Контрактный тест обслуживания по-прежнему требует HEALTHY.

На хосте работают таймеры ci-runner-disk-guard.timer (ежечасно),
ci-runner-cleanup.timer (ежедневно) и docker-ci-gc.timer (еженедельно).
pressure проверяет подтверждённые осиротевшие QA-ресурсы даже при обоих
дисках ниже 80%; прежняя очистка логов, scratch и старых временных томов
в режиме pressure выполняется только при достижении 80%.
daily выполняет ограниченную очистку всех разрешённых категорий.
При активности любого Runner.Worker удаление откладывается.
Пороги, расписание и обязательные проверки не изменены.

## Жизненный цикл мобильной QA-БД

Workflow вызывает `python3 ops/ci-runner/billok-qa-resources.py start`.
Создаются только контейнер billok-mobile-qa-<run_id>-<attempt> и его
именованный том billok-mobile-qa-data-<run_id>-<attempt>. Оба объекта
маркируются ru.billok.project=billok, billok.ci.ephemeral=true,
ru.billok.component=mobile-qa-postgres, billok.ci.run, billok.ci.attempt и
случайным идентификатором создания billok.ci.owner (не секрет авторизации).
Идентификатор сохраняется в GITHUB_ENV до создания тома. Коллизия имени,
неверная метка или неожиданное подключение приводят к отказу без
присвоения чужого объекта. PostgreSQL 16 остаётся временным и доступен
только через loopback-порт.

Шаг always() вызывает cleanup: проверяет идентичность объектов и их
связь, удаляет контейнер по полному ID с -f -v, затем отдельно удаляет
именованный том без force. Том не удаляется, если связан с любым
контейнером. Ошибка возвращается в CI, повтор после успешного удаления
безопасен. Для частично созданного ресурса действует та же проверка
идентификатора. При жёстком прерывании runner, когда always() не выполнился,
остатки обрабатывает периодическая очистка.

## Изоляция очистки

Разрешены только:

- старые логи BillOK runner (/opt/actions-runner-billok/_diag/*.log);
- старые /tmp/billok-* за исключением путей Node, backup, deploy, release,
  secret, sign, keep и production; только без новых файлов за 24 часа,
  символических ссылок и монтирования внутри;
- Docker volumes только с именем billok-ci-temp-*, меткой
  billok.ci.ephemeral=true, без присоединённых контейнеров, старше 72 часов;
- мобильные QA-контейнеры и именованные тома TASK-BILLOK-009:
  строгое имя, полный набор согласованных меток, возраст не менее 24
  часов, подтверждённый завершённый запуск и попытка именно workflow
  BillOK CI в kurt525/billok. Для контейнера также проверяются образ,
  тестовая БД, сеть, loopback-порт, ожидаемый том и отсутствие активных
  клиентских подключений. При повторном запуске более новой попытки
  проверяются текущий запуск и точная завершённая старая попытка.
  Проверка осуществляется через публичный GitHub API без токена,
  с TLS, тайм-аутами и ограничением числа запросов; при отсутствии
  подтверждения объект пропускается. Dry-run не удаляет ресурсы.
  Удаление выполняется под существующим flock; перед действиями
  повторно проверяется отсутствие активного CI worker и подключений.

Удаление общих Docker images, build-cache, контейнеров других проектов,
неподтверждённых и исторических анонимных volumes запрещено.
Другие проекты и службы не затрагиваются. Если места всё ещё не хватает,
необходим ручной аудит, а не более агрессивная глобальная очистка.
Скрипт журналирует число найденных, удалённых и оставшихся ресурсов,
причины пропусков, место на обоих дисках до и после. Секреты и полный
вывод docker inspect в журнал не передаются.

## Установка

Исходники: ops/ci-runner/. Перед установкой выполнить bash -n обоих shell-файлов,
python3 scripts/test_ci_runner_maintenance.py и
python3 scripts/test_billok_qa_resources.py. Установка только после
согласования владельцем и приёмки проверенного коммита. Сохранить резервную
копию /usr/local/sbin/ci-runner-cleanup и /usr/local/sbin/docker-ci-gc.
Сначала установить проверенный billok-qa-resources.py в /usr/local/sbin/
(root:root, 0755, без symlink), затем атомарно обновить ci-runner-cleanup.
Root-скрипт вызывает только установленную root-копию, не рабочее дерево Git
и не пользовательские пути. Если помощник отсутствует или небезопасен,
очистка QA не выполняется и проверка возвращает ошибку.
Системные таймеры не переустанавливать: следующие запуски подхватят
утверждённые файлы. Не расширять права sudo и не менять Docker daemon.

После установки — root dry-run и штатный запуск по согласованию:

    sudo env CI_CLEANUP_DRY_RUN=1 /usr/local/sbin/ci-runner-cleanup daily
    bash /usr/local/sbin/ci-runner-cleanup status
    systemctl list-timers --all
    systemctl is-active actions.runner.kurt525-billok.msk-1-vm-0w12-billok.service

При случайном сбое CI повторять только упавшее задание без коммита,
если код не изменился. Приёмка TASK-BILLOK-009: все пять заданий
на одном SHA, результаты тестов в PR, подтверждённая установка
на ci-runner, проверка отсутствия новых осиротевших QA-томов.
Изменение закреплённого workflow в production-механизме допуска
требует отдельного согласования; не обходить проверку совместимости.
